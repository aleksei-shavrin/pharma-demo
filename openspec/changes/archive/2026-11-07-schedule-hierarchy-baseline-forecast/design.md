# Design: иерархия календарного плана

## Context

R1 и R2 согласованы 2026-11-06. Портфель остаётся read-model внутри `PRJ-01` ([ADR-0006](../../../docs/06-architecture/decisions/0006-portfolio-program-project-read-model.md)). G07–G11 уже отдают плоские работы и связи. Файл аналитика не содержит дат, процентов и типов SS/SF/FF/FS. Знаки `→` и `⇢` не становятся типом стрелки.

## Goals / Non-Goals

**Goals:**

- Один список видимых строк для таблицы и диаграммы.
- Дерево показа на снимке C и прежний кластер WK.
- Прогресс 0 отличим от неизвестного. Прогресс группы неизвестен.
- Прогнозная полоса обязательна для работы. Базовый интервал необязателен.
- В приложении базовая полоса рисуется над прогнозной, если заданы оба конца интервала. Строка, где одновременно есть база и зависимость, в продукт не входит и остаётся только в лаборатории.

**Non-Goals:**

- Новый id портфеля, программы как строки календаря, факт, CPM, PRO baselines и split, закрытие C07 и E02.

## Decisions

1. Ключ строки — `kind:id`. Выбор хранит ключ, не номер.
2. `parentKey` — такой же ключ или `null`. Родитель берётся из структуры показа, не из колонки связей.
3. `wbs` — стабильный код (`8`, `8.2`, `8.2.1`, `8.2.3`) и не равен номеру видимой строки.
4. `siblingOrder` упорядочивает детей одного родителя. Строки без родителя, кроме корневой группы, сохраняют прежний порядок дата → kind → id и идут после дерева.
5. `progressPct: number | null`. `0` — известный ноль. `null` — нет данных, подпись «нет данных». Статус работы процент не задаёт.
6. Группа всегда `progressPct: null`. Сводный диапазон — от самой ранней до самой поздней прогнозной границы детей, у которых интервал есть. Точка вехи входит как дата прогноза. Если интервалов нет, сводной полосы нет.
7. `sourceWeeks` — целое число недель с той строки, где в исходнике стоит `⚠️Nн`, иначе `null`.
8. Предупреждение вычисляет клиент, отдельного поля API нет. Приоритет: оба края базы и прогноза заданы и интервалы различаются → «Прогноз отличается от базового плана». Иначе `Delayed` или `sourceWeeks` → «Отставание» и недели, если они есть на строке. Иначе иконки нет. Группа предупреждает, если отметка есть у неё или у потомка. Сравнение с `scenarioAsOfDate` не включается.
9. Прогноз работы — `startDate`/`endDate`, конец включителен. База — `baselineStart`/`baselineEnd` оба или оба пусты. Пустая база не создаёт узел. Факт не хранится.
10. `MS-CLN-PANEL` на C — одна строка прежнего id, `parentKey` = `stage_group:8.2`, `wbs` = `8.2.3`. На A, D и F родитель и wbs пустые, id тот же.
11. Связи остаются `work:<id>` между WK. На `8.2.*` связей нет. Стрелка крепится к прогнозной задаче. Сочетание базы и зависимости на одной строке в подвыборке C отсутствует.
12. Владелец видимых строк один: множество раскрытия, фильтр, выбранный ключ, `visibleOrdinal` с 1. По умолчанию на C открыты `project_group:AN-08` и `stage_group:8.2`.
13. Режим приёмки нового календаря — «Временная шкала»: колонки приложения и область задач DHTMLX со `show_grid: false`. «Разделение» по умолчанию не меняется.
14. Адаптер DHTMLX принадлежит основному Gantt. Модуль базы подключён в приложение после лаборатории. Лабораторная пара `B-src` → `B-base` со стрелкой `lab-fs` в фикстуры продукта не копируется.

## Risks

- Две копии `MS-CLN-PANEL` сломают показ. Сервис обновляет существующую веху, а не добавляет вторую.
- `progressPct: 0` нельзя опускать как falsy.
- Split не показывает стрелки. Приёмка стрелок идёт в «Временной шкале».
- Если бы лаборатория сравнения не прошла, основной план остался бы с одной прогнозной полосой. Лаборатория прошла: в приложении базовая полоса рисуется над прогнозом там, где интервал задан. Это не фактический интервал и не закрывает C07.
