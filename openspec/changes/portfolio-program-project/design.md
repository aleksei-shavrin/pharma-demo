# Design: портфель, программы, проекты

## Context

`PRT-01` и снимки 01–19 уже держат HVAC, панели, энергоснабжение и `DEC-001`. Направления `WS-*` остаются измерением оборудования и проблем. Семь программ существуют только в отчёте A01. Исходник аналитика — одна картина статусов, не ряд снимков.

## Goals / Non-Goals

**Goals**

- Показ 03 → 04 → 06: портфель, выбор программы, дашборд программы, проблема панелей, карточка `AN-08`, состав и возврат.
- Один ID вехи, видимый и в 12, и в своей программе, если заданы оба признака.
- Тонкие строки не закрашивают известное отставание исходника в Green.

**Non-Goals**

- E04–E05, F07, полный WBS, критический путь, смена варианта 1 шкалы.
- Новая причинность поставка → монтаж панелей.
- Проверка поведения `reference platform` в этом change. E03 только отделяет уже увиденные маршруты от гипотез.

## Decisions

### Принадлежность и видимость

- `programId` и `projectId` — куда веха входит. `null` допустим.
- `portfolioVisible` — входит ли ID в стабильные 12.
- Представление без программы: `portfolioVisible = true`.
- Представление программы: `programId` равен выбранному. Сюда попадают и портфельные вехи этой программы.
- `MS-PS`: `programId` null, `projectId` null, `portfolioVisible` true.
- `MS-CLN-PANEL`: `PRG-CON`, `AN-08`, `portfolioVisible` true.
- `MS-UTL-PWR`: `PRG-ENG`, `AN-24`, `portfolioVisible` true.
- `PRG-DSN`, `PRG-DIG`, `PRG-ORG` не получают вех. Пример пустой шкалы — `PRG-DSN`.
- Остальные 12 распределяются так: `MS-BLD-EXC` → `PRG-CON` / `AN-06`; `MS-BLD-ENCL` → `PRG-CON` / `AN-07`; `MS-CLN-RDY` → `PRG-CON` / `AN-08`; `MS-HVAC-IQ` → `PRG-ENG` / `AN-09`; `MS-UTL-WFI` → `PRG-ENG` / `AN-10`; `MS-PRD-INST` → `PRG-EQP` / `AN-13`; `MS-PKG-SAT` → `PRG-EQP` / `AN-14`; `MS-COM-OQ` и `MS-COM-GO` → `PRG-STA`, `projectId` null.

Три рендерера вызывают один резолвер уже отфильтрованного списка. Вариант 1 — основной.

### Статусы

- Подробные `AN-08`, `AN-09`, `AN-24` следуют существующим снимкам вех и HVAC: Green на 01–02, Red на 03–19.
- `AN-06` и `AN-07` подробны как строки состава (имя, синтетический владелец, ход без недель исходника), статус Yellow на всех снимках: в исходнике есть ⚠️ и ❌, а их вехи обзора остаются Green.
- Тонкая строка: имя и программа из исходника; `sourceAttention` из наличия ⚠️/❌; владелец «не назначен»; даты и ход «нет в этом показе». Статус Yellow при `lag`, Green при `none`, на всех 01–19.
- Статус программы — максимум статусов проектов. Пустая шкала его не повышает и не понижает.
- Фильтр «Требует внимания» оставляет Yellow и Red. Сброс снимает только фильтр.

### Навигация и снимок

- «Программы» → `/programs`. Строка → `/programs/:id`. Ссылка «Состав» → `/programs/:id/projects`.
- «Проекты» → `/projects`. Строка → `/projects/:id`.
- Клик по программе на `/` ставит или снимает `?program=`. «Перейти к программе» ведёт на `/programs/:id`.
- Снимок — сессия. Смена снимка не трогает query и не уходит со страницы программы.
- «Назад» восстанавливает URL, включая `?program=`, и не восстанавливает прежний снимок.
- Прямой URL неизвестного ID — отказ, не пустая страница.

### Поля

| Поле | Откуда |
|------|--------|
| Имя проекта, номер, программа | исходник и таблица A01 |
| `sourceAttention` | наличие ⚠️ или ❌ в блоке исходника |
| Статус и даты `AN-08`, `AN-09`, `AN-24` | уже заданные снимки вех и HVAC |
| Владелец и ход `AN-06`, `AN-07` | синтетика, без новых недель |
| Владелец, даты и ход тонких строк | синтетическое отсутствие: «не назначен», «нет в этом показе» |
| Статус тонкой строки | правило `sourceAttention`, одинаковое на 01–19 |

## Risks / Trade-offs

- Yellow на всех снимках для тонких отставаний грубее, чем сюжет C. Иначе Green противоречил бы исходнику.
- `PRG-STA` получает две вехи запуска без проекта. Это принадлежность программы, не новый проект.
