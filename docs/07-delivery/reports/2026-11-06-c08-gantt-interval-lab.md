# C08 — что рисует установленный DHTMLX Community

Страница `apps/web/scripts/gantt-interval-lab/` открыта статическим сервером с корнем `apps/web`. Это не маршрут приложения и не `/schedule`. Адаптер продукта не менялся. Поставка `dhtmlx-gantt@10.0.3`.

## Что подтвердил экземпляр

| Проверка | Результат |
| --- | --- |
| `gantt.license` | `mit` |
| `typeof addTaskLayer` | `undefined` |
| `render: "split"`, `open_split_tasks`, `split_placement: "inline"` | Одна сводная полоса на родителя. У короткой ширина 350px на строку, у длинной 1330px. Двух полос на одной строке нет |
| Стрелка FS между детьми split | `TypeError: Cannot read properties of undefined (reading 'render_mode')` |
| Overlay `getTaskPosition` + `posFromDate` | Три дополнительные полосы: база короткой, база длинной, факт длинной. Факта у короткой нет, и полоса факта для неё не создаётся |
| Прогноз | Остаётся штатной полосой: короткая 70px (один день, 2027-03-02), длинная 700px (10 дней, с 2027-03-01) |
| Стрелка FS после overlay | Одна, `type: "0"`, source `short-forecast`, target `long-forecast`. Крепится к прогнозным задачам, не к полосам базы и факта |
| Темы | Фон сетки светлый `rgb(247, 244, 239)`, тёмный `rgb(28, 25, 21)`. Ширина короткой полосы в обеих темах 70px |

Кадры: `/tmp/pharma-demo-artifacts/c06/gantt-lab-light.png`, `gantt-lab-dark-chart.png`.

Своя логика overlay — расчёт `left`/`width`/`top` и три абсолютных узла. Это больше, чем включить опцию библиотеки, и меньше, чем второй адаптер: тот же приём, что ghost-маркер контрольной точки, но для интервала.

## Что это не решает

Перенос в `/schedule` не сделан. Макет ОСУП по-прежнему должен назвать две полосы из базы, прогноза и факта, основную полосу, вертикальный порядок, цвет отклонения, неполный факт, крепление стрелки и связь со строкой таблицы. Пока ответа нет, календарный план остаётся с одной прогнозной полосой на работу.

Интегратор на снимке C открыл «Временная шкала»: у `work:WK-01`…`work:WK-05` по одной полосе.
