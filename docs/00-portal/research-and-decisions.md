# Исследование стека документации и решения

Краткое резюме выбора docs-стека. Детали решения — в [ADR-0001](../06-architecture/decisions/0001-documentation-stack.md).

## Выбранное направление

> **certainty:** hypothesis
>
> Целевой docs-стек: **Docusaurus** (сайт из Markdown), **OpenSpec** (спеки изменений рядом с разработкой), **локальный поиск** на сайте документации (без обязательной внешней SaaS-поиска на старте).

## Почему не альтернативы

> **certainty:** hypothesis
>
> **Zensical** отклонён как основной портал: не закрывает согласованный контур «docs-сайт + привычный MD-workflow + локальный поиск» лучше Docusaurus для текущего плана.

> **certainty:** hypothesis
>
> **Spec Kit** как параллельный «второй» контур спецификаций отклонён: риск дублирования с OpenSpec и рассинхрона источников истины. Один контур спецификаций изменений — OpenSpec.

## Связь с кодом и ADR

| Тема | Где зафиксировано |
|------|-------------------|
| Docs stack | ADR-0001 |
| Технологический стек приложения | ADR-0002 + product docs |
