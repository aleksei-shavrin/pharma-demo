# ADR-0006: Портфель, программы и проекты как read-model

- **Статус решения:** accepted (направление; document `status` остаётся `draft`)
- **Дата:** 2026-11-06
- **Review:** 2026-11-06, контракт S0 согласован без изменения требований
- **Superseding note (2026-11-09):** пункт 1 ниже дополнен явным решением пользователя о id контейнера `PRT-01`. Document `status` не повышался; human ADR review этого дополнения отдельно не заявлялся.

## Контекст

Показ идёт от портфеля к программе и проекту. Контракты `MS-PS`, `DEC-001` и HVAC привязаны к контейнеру портфеля (исторически обозначался `PRJ-01`). Восемь направлений описывают оборудование и проблемы, а не семь программ отчёта A01. Исходник аналитика содержит отставания почти во всех 25 блоках, но не даёт снимков A–S.

Норматив change: `openspec/changes/portfolio-program-project/`.

## Решение

> **certainty:** assumption (п.2–6); п.1 — **user decision 2026-11-09** (не AI hypothesis)

1. ~~`PRJ-01` остаётся контейнером завода; новый ID портфеля не вводится.~~ **Superseded 2026-11-09 (user decision):** канонический id контейнера портфеля — **`PRT-01`**. Legacy `PRJ-01` в активном коде/данных/примерах контрактов заменяется на `PRT-01`. Реальные проекты аналитика остаются `AN-*`, программы — `PRG-*`. Пути API `/v1/projects/{id}` и имя поля `projectId` в этой волне сохраняются как technical slot; значение контейнера — `PRT-01`. Отображаемое имя — «Строительство фармацевтической фабрики (Greenfield)». Короткая подпись «Портфель 01» живёт отдельно от этого имени и от id. Исторические audit/handoff с `PRJ-01` не переписываются как будто id не существовал.
2. Семь программ и 25 проектов — read-model внутри этого контейнера. Это не Domain WBS и не замена Schedule.
3. Направления `WS-*` сохраняются. Правый блок обзора их больше не показывает.
4. У вехи один ID. Принадлежность (`programId`, `projectId`) и видимость в подборке из 12 (`portfolioVisible`) задаются отдельно. Одна и та же веха может быть видна в обоих представлениях.
5. Тонкая строка с ⚠️ или ❌ в исходнике не бывает Green. Отсутствие подробных дат не улучшает статус программы.
6. Выбор программы на обзоре — query. Переход на страницу программы — отдельная ссылка. Снимок живёт в сессии и кнопкой «Назад» не откатывается.

## Последствия

- Даты `MS-CLN-PANEL`, `MS-UTL-PWR` и `MS-PS` на C–S не пересматриваются.
- `PRG-DSN` может быть Yellow и при этом не иметь вех.
- Код API и страниц начинается после review change.
- Активные fixtures/defaults/tests/docs examples используют `PRT-01` для контейнера; `PRJ-99` и прочие nonexisting id остаются негативными.
