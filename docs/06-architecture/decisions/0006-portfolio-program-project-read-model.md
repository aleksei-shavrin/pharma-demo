# ADR-0006: Портфель, программы и проекты как read-model

- **Статус решения:** accepted (направление; document `status` остаётся `draft`)
- **Дата:** 2026-11-06
- **Review:** 2026-11-06, контракт S0 согласован без изменения требований

## Контекст

Показ идёт от портфеля к программе и проекту. Контракты `MS-PS`, `DEC-001` и HVAC уже привязаны к `PRJ-01`. Восемь направлений описывают оборудование и проблемы, а не семь программ отчёта A01. Исходник аналитика содержит отставания почти во всех 25 блоках, но не даёт снимков A–S.

Норматив change: `openspec/changes/portfolio-program-project/`.

## Решение

> **certainty:** assumption

1. `PRJ-01` остаётся контейнером завода. В текстах обзора это портфель. Новый ID портфеля не вводится.
2. Семь программ и 25 проектов — read-model внутри этого контейнера. Это не Domain WBS и не замена Schedule.
3. Направления `WS-*` сохраняются. Правый блок обзора их больше не показывает.
4. У вехи один ID. Принадлежность (`programId`, `projectId`) и видимость в подборке из 12 (`portfolioVisible`) задаются отдельно. Одна и та же веха может быть видна в обоих представлениях.
5. Тонкая строка с ⚠️ или ❌ в исходнике не бывает Green. Отсутствие подробных дат не улучшает статус программы.
6. Выбор программы на обзоре — query. Переход на страницу программы — отдельная ссылка. Снимок живёт в сессии и кнопкой «Назад» не откатывается.

## Последствия

- Даты `MS-CLN-PANEL`, `MS-UTL-PWR` и `MS-PS` на C–S не пересматриваются.
- `PRG-DSN` может быть Yellow и при этом не иметь вех.
- Код API и страниц начинается после review change.
