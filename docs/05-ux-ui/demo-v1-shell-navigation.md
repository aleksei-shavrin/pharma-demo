# Demo v1 Application Shell and navigation

> **certainty:** hypothesis
>
> Shell / nav: D1, D2, D7, D9 и связанные — `approved UX decision` для Demo v1. Не предписывает OpenSpec UI SHALL. FE narrative data — только через HTTP API (REQ-NFR-001), когда появится apps.

## 1. Application Shell regions

```text
┌─ AppShell ─────────────────────────────────────────────┐
│ ┌ Sidebar ┐ ┌─ Top Application Bar ──────────────────┐ │
│ │ РАНДОК.Платформа │ │ Breadcrumbs │ Bell │ Theme │ Snapshot  │ │
│ │ Nav×5   │ ├─ Page Surface ─────────────────────────┤ │
│ │ Docs ↓  │ │  Page header + Main content            │ │
│ └─────────┘ └────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

| Region | Role | Decision Status |
|--------|------|-----------------|
| Left Sidebar | Primary IA (5 пунктов) + footer «Документация» | `approved UX decision` (D2, D9, F02) |
| Top Application Bar | Breadcrumbs; Bell (уведомления); Light/Dark; Snapshot A/B/C — **без** длинного бейджа PRJ/завод/снимок | `approved UX decision` (F04–F05) |
| Page Surface | Elevated plate (фон, радиус, тень) — контент страницы | `approved UX decision` |
| Main content | KPI / tables / charts / detail | — |

Стек: **shadcn/ui**, **TanStack Table**, **Recharts** — `approved UX decision`. Gantt lib — **RESOLVED** (ADR-0004, I7).

### 1.0 Scroll ownership

> **certainty:** fact
>
> Документ (`html`/`body`) **не** скроллится: `height: 100dvh; overflow: hidden` в `globals.css`. AppShell — `fixed inset-0` + `overflow-hidden` (вне потока документа), иначе высокий контент внутри `#main-content` раздувает `documentElement.scrollHeight` и даёт второй скроллбар у края окна. Единственный page-level вертикальный скролл — `#main-content` на Dashboard canvas или `PageContent` (`mode="page"`) на остальных экранах. Карточки со списками (исключения, решения) и workspace (график) могут иметь собственный bounded scroll. Двойной скролл «документ + main» — дефект.

### 1.1 Выравнивание хедеров (F06)

Нижняя граница строки бренда в сайдбаре и нижняя граница Top Application Bar лежат на **одной горизонтали** (общая линия разделителя shell). Обе зоны используют `h-[var(--topbar-height)]` и `border-b` на одном уровне; после изменений App Bar (F04–F05) при необходимости подгоняют padding/высоту, чтобы не было «ступеньки» (~4px — ориентир для визуальной проверки).

### 1.2 Dev-only: индикатор Next.js (F01)

Круглый индикатор с молнией (Dev Overlay `StaticIndicator`) **не** часть продукта. В локальной dev-сборке отключается в `apps/web/next.config.ts` (`devIndicators` / API Next 15.1). Не путать с UI приложения.

### 1.3 Свёрнутый сайдбар и F07

> **certainty:** fact (источник и удаление, 2026-11-06)

**AS-IS:** в `AppShell` / `Sidebar` **нет** режима collapse / icon-rail; ширина фиксирована `--sidebar-width` (240px). Токен `sidebar-width-collapsed` в foundations — резерв, не подключён.

**Ожидание F07 (если элемент воспроизводится):** кнопка **над** свёрнутым сайдбаром открывает постороннюю панель (не primary IA). Элемент и доступ к этой панели **удалить**. После удаления основная навигация работает в развёрнутом и (если появится) свёрнутом состоянии.

**Если не воспроизводится:** зафиксировать URL, сборку (Compose/`HOST_PORT`), viewport и отсутствие кнопки; пункт F07 остаётся открытым. Не путать с F01 (молния) и с `buildActivity` Next (низ справа).

Повтор 2026-11-06 на Compose `http://127.0.0.1:3080`: ширина окна 1287px и 1100px, сайдбар 240px. Над сайдбаром только скрытая ссылка «Перейти к основному содержимому» (skip-link, верх −32px). Кнопки collapse нет. Индикатор Next.js в этой сборке не показан.

Повтор той же даты на `next dev` `http://127.0.0.1:3000/`: обычное окно 1714×1281 и 1100×800, сайдбар 240px. Клик по тексту бренда меню не открывает. Над хедером сайдбара только skip-link с `top: -32px`.

Источник зелёной панели — эта ссылка. Текст ровно «Перейти к основному содержимому», компонент `skip-link.tsx`, класс `.skip-link`. Вне фокуса она уехала вверх (`translateY(-120%)`). По Tab фон `var(--primary)` выезжал над хедером сайдбара. Ссылка вела на `#main-content` и сама была пунктом в порядке Tab. Панель и этот пункт удалены. Идентификатор области `#main-content` остаётся у основного содержимого. Кнопка меню ниже 1024px не эта панель и сохранена.

Проверка после удаления, `next dev` `http://127.0.0.1:3000/`, окно 1440×1000: текста «Перейти к основному содержимому» нет, первый видимый переход по клавиатуре — «Дашборд», затем разделы до «Персоны» и «Документация». На 390px кнопка «Открыть меню» на месте и закрыта. **F07 закрыт** этим удалением. Drawer §1.4 F07 не закрывал.

Drawer ниже 1024px (§1.4) — отдельное правило узкой ширины. Он не является кнопкой над свёрнутым сайдбаром и F07 не закрывает.

## 1.4 Меню поверх страницы ниже 1024px

> **certainty:** assumption
>
> Согласовано для демо 2026-11-06 вместе с адаптивностью календаря. Не закрывает F07 (§1.3) и не вводит icon rail 64px.

Ниже 1024px сайдбар не стоит в потоке. Он закрыт по умолчанию и открывается поверх страницы. Внутри — те же разделы и «Документация».

Кнопка в верхней панели, слева от крошек:

- доступное имя «Открыть меню» или «Закрыть меню»;
- сообщает, открыто ли меню (`aria-expanded`);
- указывает на панель меню.

Открытие переносит фокус в меню. Escape закрывает меню и возвращает фокус на кнопку. Переход по ссылке раздела закрывает меню. Клик по затемнению закрывает меню.

Селектор снимка остаётся в верхней панели, видимым и нажимаемым. Длинная подпись может обрезаться визуально; доступное имя кнопки сохраняет букву и дату снимка.

На ширине 1024px и выше сайдбар снова в потоке, ширина `--sidebar-width` (240px). Кнопки меню нет. Появление сайдбара сужает колонку содержания примерно на 240px: календарь выбирает ряд или столбец по фактической ширине своей области, не по ширине окна.

## 2. Sidebar (D9)

### 2.1 Primary IA

| Order | Item (RU) | Route (illustrative) |
|-------|-----------|----------------------|
| 1 | **Дашборд** | `/` |
| 2 | **Программы** | `/programs` |
| 3 | **Проекты** | `/projects` |
| 4 | **Календарный план** | `/schedule` |

| 6 | Проблемы и риски | `/issues-risks` |
| 7 | Вехи | `/milestones` |
| 8 | Персоны | `/people` |

> **certainty:** approved UX decision (G12, 2026-11-06)
>
> Пользовательская подпись раздела Schedule — **«Календарный план»** (не «График»). Маршрут **`/schedule` без изменения** (прямой вход и sidebar href). Источник подписей nav/breadcrumb — `NAV_ITEMS` / `crumbForPath` в `navigation.ts`. **Владелец правок сайдбара (G12 + F07):** FE shell (`apps/web/src/components/shell` + `lib/navigation.ts`).

Первый пункт IA — **«Дашборд»**. Остальные подписи — как в таблице.

> **certainty:** assumption
>
> Подпись раздела людей — **«Персоны»**. Маршрут **`/people` без изменения**. Та же строка стоит в хлебных крошках (`crumb` в `NAV_ITEMS` и `crumbForPath`). Прежняя подпись «Люди» в R2-документах — имя решения той волны, не текущая подпись меню.

### 2.1.0 Бренд сайдбара

> **certainty:** assumption
>
> В хедере сайдбара точная строка **«РАНДОК.Платформа»**: «РАНДОК» целиком кириллицей и прописными, после точки пробела нет. Та же строка видна в меню поверх страницы ниже 1024px, потому что это тот же `Sidebar`. Прежняя подпись «Randoc. Платформа» заменена этим уточнением.

### 2.1.1. Программы и проекты (B03, D03)

> **certainty:** assumption
>
> Контракт страниц: [ADR-0006](../06-architecture/decisions/0006-portfolio-program-project-read-model.md). Выбор программы на дашборде этим пунктом не заменяется.

| Пункт | Куда ведёт | Дальше |
|-------|------------|--------|
| Программы | `/programs` — семь программ и их статус | строка открывает `/programs/:id`; со страницы программы ссылка «Состав» ведёт на `/programs/:id/projects` |
| Проекты | `/projects` — 25 проектов | строка открывает `/projects/:id` |

Клик по программе в блоке «Состояние по программам» только ставит или снимает `/?program=`. На страницу программы ведёт кнопка «Перейти к программе».

Кнопка «Назад» возвращает предыдущий URL. Если на обзор вернулись с `?program=PRG-CON`, программа снова выбрана. Смена снимка на странице программы остаётся в сессии: «Назад» не возвращает прежний снимок. Прямой URL неизвестного ID показывает «Запись не найдена в этом снимке». `/workstreams/:id` по прямой ссылке сохраняется и в сайдбар не входит.

Dashboard / Дашборд — стартовая страница (D1). Один shell для Director и PM (D7).

## 3. Top Application Bar (F04–F05)

| Зона | Содержимое |
|------|------------|
| Слева | Breadcrumbs |
| Справа (порядок) | **Bell** (уведомления) → **Theme** (Light/Dark) → **Snapshot** A/B/C |

### 6.1 Крошки демо и контракт платформы (E04)

> **certainty:** fact для прочитанного кода; hypothesis для предлагаемого контракта. Экраны `reference platform` не открывались. Крошки демо и `reference platform` этим этапом не меняются.

Подтверждено кодом демо, [breadcrumbs.tsx](../../apps/web/src/components/shell/breadcrumbs.tsx): цепочка не состоит из ссылок. Корневой элемент навигации портфеля показывает **«Портфель 01»**: отдельного публичного идентификатора портфеля нет, `PRJ-01` остаётся внутренним id контейнера, URL и контрактов API ([ADR-0006](../06-architecture/decisions/0006-portfolio-program-project-read-model.md)). На дашборде цепочка — `Портфель 01 / Дашборд`. Дальше — `Портфель 01 / раздел / id`. Снимка в крошках нет. `/programs/PRG-CON/projects` показывает те же крошки, что и страница программы: третий сегмент «Состав» не попадает в цепочку. `/projects/AN-08` показывает `Портфель 01 / Проекты / AN-08` и не сохраняет программу. Карточка не знает, открыта она из программы или из списка `/projects`. Возврат в программу — ссылка имени программы и история браузера.

Подтверждено кодом `reference platform`: списки и карточки портфеля, программы и `/app/projects-legacy` имеют крошки своего раздела. Карточка проекта в `projects-legacy/[projectId]/_container/ProjectViewCard.tsx` даёт только «Проекты → проект». Портфель и программа встречаются ссылками в теле карточки, не в крошках. Сессии снимка демо в этом коде нет.

Предлагаемый контракт платформы, не факт экрана: прямой адрес карточки проекта стабилен. Крошки строятся из данных карточки, не из предыдущей страницы: портфель → программа → проект. Клик по программе открывает карточку программы. Вход из общего списка проектов даёт ту же цепочку. Снимок и выбранная программа этим контрактом не обещаются.

Проверка на рабочей сборке платформы, когда есть вход:

1. Открыть `/app/portfolios` и карточку одного портфеля. Записать текст крошек.
2. Открыть `/app/programs` и карточку программы. Записать текст крошек.
3. Открыть `/app/projects-legacy`, затем карточку проекта из списка. Записать крошки.
4. Открыть тот же проект прямым адресом. Сравнить крошки с шагом 3.
5. Нажать ссылку программы в теле карточки и проверить, что открылась карточка этой программы.
6. Отдельно отметить, есть ли на этих экранах снимок или выбранная программа. Их отсутствие не опровергает шаги 1–5.
