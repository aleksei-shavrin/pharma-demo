# Demo v1 — сценарий живой демонстрации

Операторская шпаргалка для живого показа **Pharma Demo** потенциальному директору фармацевтического проекта.

Не руководство пользователя. Не архитектурный документ. Не маркетинг.

Держите эту страницу во **второй вкладке**; приложение — в основной.

Селектор снимков в AppBar: компактный триггер **Снимок X · дата** → раскрытие **A–H**. Главный punch — **C**.

---

### Перед стартом

- [ ] Compose `app` поднят; [http://localhost](http://localhost) открывается
- [ ] Выбран **Снимок A**, светлая тема
- [ ] Масштаб браузера нормальный (~100%)
- [ ] Эта инструкция открыта во второй вкладке
- [ ] Готовы сказать **главную мысль** в конце шага C и в финале

> **Главная мысль Demo**
>
> Система не просто показывает красный статус.
> Она связывает конкретную задержку оборудования
> с проблемой, риском, контрольной вехой,
> влиянием на дату запуска производства
> и управленческим решением — и честно отличает
> «решение зарегистрировано» от «сроки восстановлены».

## Иерархия календарного плана

Короткий показ HVAC выше остаётся. Этот эпизод вставляется в маршрут C → D → F и возвращает на «Дашборд». Полный текст — [walkthrough](../../03-product/demo-v1-acceptance-walkthrough.md#иерархия-календарного-плана), чеклист — [отчёт](../../07-delivery/reports/2026-11-06-calendar-hierarchy-acceptance.md). E02 этот показ не закрывает.

> **certainty:** fact
>
> Прогон 2026-11-07, `http://127.0.0.1:3000/schedule`, снимок C, окно 1440×900. По умолчанию нажата иконка «Разделение»; «Таблица», «Разделение» и «Временная шкала» — имена иконок. Первая колонка — **№**; рядом ИСР (`8`, `8.2`, `8.2.1`, `8.2.2`, `8.2.3`; без кода — «—»). Предупреждение — иконка. Прогресс работы — полоса и процент; у группы/вехи/оборудования «—» («Прогресс не применяется»); у работы без процента — «нет данных», отдельно от 0%. Сравнение — иконки «Базовый план / прогноз» и «Базовый план / факт» в toolbar правее «Тип точки».

1. Откройте «Календарный план».
2. Если на кнопке снимка не C — выберите снимок C. Скажите: «Снимок C».
3. Режим уже «Разделение»: эта иконка нажата. «Временная шкала» оставляет только диаграмму и прячет таблицу — в этом эпизоде её не нажимайте.
4. Свежая сессия: снимок A и «Разделение». После C первая строка — «Внутренняя отделка и чистые помещения», в колонке ИСР код 8, букв AN-08 нет. Если свёрнута — разверните. Вторая строка — «Чистые помещения классов C/D», в ИСР код 8.2; разверните, если свёрнута. Пустой код ИСР — «—».
5. Предупреждение второй строки — иконка без текста в ячейке. Наведите курсор или переведите фокус и прочитайте имя: «Отставание, 3 нед.»
6. «Сэндвич-панели и герметизация» — 0%. «Фальшполы и потолки» — 40%. «Монтаж панелей чистых зон завершён» — ромб, одна строка.
7. На «Фальшполы и потолки»: верхняя полоса — база, нижняя — прогноз. У «Сэндвич-панели и герметизация» базы нет. Сравнение уже «Базовый план / прогноз». «Базовый план / факт» в этой речи не включайте и нижнюю полосу фактом не называйте.
8. Прокрутите список до «Подготовка зоны монтажа», 100%. Шкала едет вместе со списком. Рядом стрелки SS, FS, FF, SF. Поиск WK-01 стрелки убирает.
9. «Дашборд», дальше C → D → F. На F в «Управленческие решения» скажите «Решение записано». Фразу «DEC-001 зафиксирован…» из «Требует внимания» не произносите как эту отметку.

## Если директор спросит

| Вопрос | Безопасный ответ |
|--------|------------------|
| Почему ровно **+21** / **+14**? | В Demo v1 это явное правило сценария (BR-004: HVAC/RISK-001 → Production Start). Не полноценный CPM. |
| Это критический путь? | Demo показывает управленческую связку «задержка → готовность к производству». CPM здесь не демонстрируется. |
| Что после решения? | Decision **не** меняет прогноз сам по себе. Улучшение на G/H — заранее заданное состояние снимка. |
| Откуда данные? | Подготовленный сценарий A–H (2027). Не данные реального предприятия. |
| Это промышленная система? | **Demo v1** для управленческого сценария. Не заявляем GMP/CSV-валидацию продукта. |

## Что не включать в основной показ

- Портал документации «заодно»
- Переключение светлой/тёмной темы как отдельный акт
- Все вкладки карточки подряд
- Коды владельцев **SH-*** как сущности
- Долгое «гуляние» по D/E
- API / OpenAPI / архитектура

## Если что-то пошло не так

| Если | Действие |
|------|----------|
| Долгая «Загрузка…» | 1–2 с; иначе F5 в **той же** вкладке |
| Потеряли маршрут | **Обзор** → нужный снимок в селекторе A–H |
| После F5 «не тот» снимок | В той же вкладке восстанавливается последний **успешно загруженный** снимок |
| Новая вкладка | Начинается с **A** |

> F5 в той же вкладке восстанавливает последний успешно загруженный снимок **A–H** (`sessionStorage`). Новая сессия → **A**.

## Чем закончить показ

Оставайтесь на **C** (punch) или на **H** (residual honesty).

«Мы проследили путь от конкретной задержки оборудования до влияния на дату запуска и управленческого решения. Важно: система не выдаёт само решение за уже достигнутый результат.»
