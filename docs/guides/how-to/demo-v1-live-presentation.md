# Demo v1 — сценарий живой демонстрации

Операторская шпаргалка для живого показа **Pharma Project Control** потенциальному директору фармацевтического проекта.

Не руководство пользователя. Не архитектурный документ. Не маркетинг.

Держите эту страницу во **второй вкладке**; приложение — в основной.

---

## Перед показом

| Что | Значение |
|-----|----------|
| Приложение | [http://localhost](http://localhost) |
| Эта инструкция | [http://docs.localhost/docs/guides/how-to/DOC-GUIDE-001](http://docs.localhost/docs/guides/how-to/DOC-GUIDE-001) |
| Портал (корень) | [http://docs.localhost](http://docs.localhost) |
| Запуск | `docker compose --profile app up -d` (если ещё не запущено) |
| Старт UI | **Обзор**, снимок **A**, светлая тема |
| Навигация | только **боковое меню**. Не адресная строка |

### Перед стартом

- [ ] Compose `app` поднят; [http://localhost](http://localhost) открывается
- [ ] Выбран **Снимок A**, светлая тема
- [ ] Масштаб браузера нормальный (~100%)
- [ ] Эта инструкция открыта во второй вкладке
- [ ] Готовы сказать **главную мысль** (ниже) в конце шага B и в финале

> **Главная мысль Demo**
>
> Система не просто показывает красный статус.
> Она связывает конкретную задержку оборудования
> с проблемой, риском, контрольной вехой,
> влиянием на дату запуска производства
> и управленческим решением.

## Короткий показ — 3–5 мин (основной)

Рекомендуемый маршрут для первого показа.

| # | Куда | Время |
|---|------|-------|
| 1 | **Обзор** · **Снимок A** | ~30–45 с |
| 2 | **A → B** на Обзоре | ~60–90 с |
| 3 | **График** → **Временная шкала** | ~45–60 с |
| 4 | **Обзор** · **B → C** | ~60–90 с |

### 1. Обзор — снимок A

| | |
|--|--|
| **Куда** | Боковое меню **Обзор**. Убедиться: **Снимок A** |
| **Видно** | Дата состояния **15.02.2027**; поставка оборудования и запуск производства **по плану**; риск зелёный; решения не требуется |
| **Сказать** | «Проект в нормальном состоянии: критическое оборудование и запуск производства идут по базовому плану, активного управленческого исключения нет.» |
| **Не объяснять** | внутреннюю модель данных, API, как устроены тестовые данные, коды **SH-*** |
| **Дальше** | Переключить на **Снимок B** |

Не задерживаться. A нужен как исходное состояние.

### 2. A → B (центр Demo)

| | |
|--|--|
| **Куда** | Тот же **Обзор**, переключатель **B** |
| **Видно** | на дату **01.03.2027**; оборудование **Задержка** **+21 день** (15.05 → **05.06.2027**); проблема **Открыта**; риск **красный**; веха **красная**; запуск **+21 день** → **06.10.2027**; нужно управленческое решение |
| **Сказать** | «Критическое HVAC-оборудование задерживается на 21 день. Система показывает не только задержку: она связывает её с открытой проблемой, красным риском и контрольной вехой. Прогноз запуска производства сдвигается на 21 день — до **06.10.2027**. Теперь требуется управленческое решение.» |
| **Не объяснять** | расчёт критического пути / CPM; «система сама посчитала сеть работ»; что восстановление сроков уже выполнено |
| **Дальше** | Боковое меню **График** |

Провести взглядом цепочку на Обзоре: оборудование → проблема → риск → веха → дата запуска → решение.

### 3. График — временная шкала

| | |
|--|--|
| **Куда** | **График** → режим **Временная шкала** (первый) |
| **Видно** | Две строки: **EQ-HVAC-01** и **MS-PS** / готовность к производству; легенда **База** / **Прогноз**; визуальный сдвиг на **+21 день** |
| **Сказать** | «Здесь тот же эффект виден во времени: база остаётся исходной контрольной точкой, а прогноз смещён на 21 день.» |
| **Не объяснять** | сетевой график работ, WBS, CPM, зависимости, перетаскивание, автооптимизацию |
| **Дальше** | Боковое меню **Обзор**, затем **Снимок C** |

**Таблица** — только если спросят точные даты.  
**Разделение** — только если спросят «как вместе».

### 4. Обзор — снимок C

| | |
|--|--|
| **Куда** | **Обзор** → **Снимок C** |
| **Видно** | на дату **02.03.2027**; DEC-001 **«Приоритизировать восстановление сроков»**; проблема **Выполняются меры**; риск и веха **красные**; прогноз запуска всё ещё **06.10.2027** |
| **Сказать** | «Управленческое решение „Приоритизировать восстановление сроков“ зарегистрировано. Проблема уже „Выполняются меры“, но риск и веха остаются красными, а прогноз запуска — **06.10.2027**. Система различает принятое решение и фактическое восстановление сроков.» |
| **Не объяснять** | что восстановление сроков уже выполнено; что даты «сами откатились» |
| **Дальше** | Закончить показ (см. финал) |

## Если есть ещё 2–3 минуты

После шага B (или перед C), не обязательно все экраны:

| Экран | Одна мысль для директора |
|-------|--------------------------|
| **Оборудование** | Конкретный источник отклонения — **EQ-HVAC-01**, задержка **+21 день** |
| **EQ-HVAC-01** → вкладка **Связи** | Задержка связана с проблемой и риском |
| **Проблемы и риски** | Открытая проблема и красный риск в одном реестре |
| **Вехи** | Отклонение дошло до **Готовность к производству** (**+21**, **06.10.2027**) |
| Затем **График** / **C** | Как в коротком показе |

Не проходить все вкладки карточки подряд.

## Если директор спросит

| Вопрос | Безопасный ответ |
|--------|------------------|
| Почему ровно **+21 день**? | В Demo v1 это явное правило сценария: сдвиг поставки критического оборудования и согласованное влияние на дату запуска. Это не полноценный расчёт критического пути. |
| Это критический путь? | Demo показывает управленческую связку «задержка → влияние на готовность к производству». Полноценный расчёт критического пути (CPM) здесь не демонстрируется. |
| Можно изменить график? | В Demo график предназначен для просмотра: смотрим базу и прогноз, план в интерфейсе не редактируем. |
| Что после решения? | На снимке **C** решение **зарегистрировано**, по проблеме **выполняются меры**, но прогноз **ещё не восстановлен** — это сознательно. |
| Откуда данные? | Для этой демонстрации используется подготовленный сценарий с тремя состояниями проекта — A, B и C. Это не данные реального предприятия. |
| Это уже промышленная система? | Это **Demo v1** для управленческого сценария. Не заявляем готовность к промышленной эксплуатации, внедрение на конкретном предприятии или завершённую GMP/CSV-валидацию продукта. |

## Что не включать в основной показ

- Портал документации директору «заодно» (кроме вашего второго экрана-шпаргалки)
- Переключение светлой/тёмной темы
- Все вкладки карточки подряд
- Коды владельцев **SH-***
- Пустые состояния / «объект отсутствует»
- API / OpenAPI / архитектурные документы
- Долгое «гуляние» по снимку **A**

## Если что-то пошло не так

| Если | Действие |
|------|----------|
| Долгая «Загрузка…» | Подождать 1–2 с; иначе F5 в **той же** вкладке (снимок **восстановится**) |
| Потеряли маршрут рассказа | Боковое меню **Обзор** → нужный снимок **A/B/C** |
| Временная шкала пустая | Режим **Таблица**, затем снова **Временная шкала** |
| Случайно тёмная тема | Кнопка темы в шапке → светлая |
| После F5 «не тот» снимок | Проверить переключатель A/B/C; в той же вкладке должен вернуться **последний успешно загруженный** снимок |
| Новая вкладка / свежая сессия | Начинается с **A** — нормально |
| UI полностью не отвечает | `docker compose --profile app restart` → [http://localhost](http://localhost) → **Обзор** → нужный снимок |

> **Обновление страницы**
>
> F5 / обновление в **той же** вкладке восстанавливает последний **успешно загруженный** снимок A/B/C (в рамках сессии вкладки).
> Новая / независимая сессия → **A**.
> Между экранами — боковое меню, не адресная строка.

## Чем закончить показ

Оставайтесь на **Снимке C**.

«Мы проследили путь от конкретной задержки оборудования до влияния на дату запуска производства и управленческого решения. Важно: система не выдаёт само решение за уже достигнутый результат — пока сроки не восстановлены, риск и веха остаются красными.»
